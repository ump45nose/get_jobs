# Get Jobs Extension

`get_jobs` 的 Manifest V3 浏览器插件改写版。当前优先完成猎聘投递闭环，BOSS 保持关闭，智联在猎聘真实账号验收后迁移。

## 当前能力

- 直接使用用户当前 Chrome 标签页和猎聘登录态，不启动 Playwright 浏览器。
- 在猎聘页面右下角显示 `Get Jobs 助手` 悬浮入口，点击即可展开网页内固定抽屉。
- 在页内助手抽屉识别当前猎聘搜索结果页的岗位卡片。
- 使用 OpenAI 兼容接口，根据岗位快照与用户填写的完整自定义提示词生成个性化招呼草稿。
- 兼容模型偶发返回的 JSON、代码块和 `<think>` 包装；固定系统约束不再诱导模型输出“需人工判断”。
- AI 请求失败、正文为空、拒答或格式无效时，可在页面发送前切换到用户配置的兜底招呼语，并明确标记文本来源。
- 本机保留最近 20 次脱敏 AI POST 诊断；默认仅记录端点、模型、消息长度、状态与耗时，完整请求/响应必须显式开启。
- 模型输出超过 150 字或 3 句话时自动压缩一次；压缩失败或仍超限时执行只删除尾部的安全收口，发送前继续保留硬校验。
- 不对兼容模型设置固定低输出 token 上限，避免 GLM 等推理模型只返回推理过程而没有最终招呼正文；150 字限制完全由生成后的压缩与硬校验保证。
- 招呼草稿默认要求预览/编辑确认；用户可在配置中关闭确认，改为生成后直接执行。
- 由用户明确选择一个岗位后执行一次“聊一聊”，再发送 AI 招呼语并单独发送简历。
- 可在二次确认后按页面顺序处理当前页全部新岗位；单岗位内部关键动作和两个岗位之间分别使用可配置随机稳定等待，已显示“继续聊”的岗位会被跳过。
- 对默认不显示按钮的岗位，执行时先激活招聘者区域并等待动态“聊一聊”按钮出现。
- 分别等待聊天窗口、本人文本消息和本人简历卡片回执，只有明确成功才记录为完整投递。
- 聊天岗位绑定兼容猎聘省略卡片末尾 `【地区】` 的显示差异；降级匹配必须同时命中公司名。
- 若平台已经在当前聊天中产生本人简历卡片，扩展会确认该证据并跳过再次点击，避免重复发送简历。
- 兼容“选择附件简历”二次确认弹窗：仅在附件已选中且存在唯一明确的“立即投递”按钮时继续，并仍以当前聊天新增本人简历卡片作为成功回执。
- 将“继续聊”单独记录为此前已联系，不计入本次新投递。
- 遇到验证码、登录失效、页面刷新或用户停止时安全中止。
- 配置和任务状态保存在 `chrome.storage.local`，岗位与尝试记录保存在 IndexedDB。
- API Key 单独保存在本机扩展存储，并将存储访问级别限制为可信扩展页面；不会写入投递历史。

## AI 配置

1. 在页内助手抽屉填写 OpenAI 兼容 `Base URL`、模型、API Key、个人简历摘要和“AI 招呼语完整提示词”。
2. 点击“AI 与发送”模块右上角的“保存 AI 配置”，并允许 Chrome 访问该 AI 接口域名；Key 状态会由“待保存”变为“已保存”。扩展使用可选主机权限，不会在安装时申请全网访问。
3. 也可以直接点击岗位的“生成草稿”；扩展会先保存当前 AI 表单和 API Key，再调用模型。
4. “AI 请求超时”默认 120 秒，可按模型速度在 10 至 600 秒范围内调整。
5. “AI 请求或输出无效时使用兜底招呼语”默认开启；兜底文本可编辑，仍必须满足 150 字和 3 句话限制。
6. “发送前预览并允许编辑”默认开启；关闭后，岗位按钮会显示“生成并投递”。
7. “AI 招呼成功后单独发送简历”默认开启，可按需要关闭。
8. 展开“AI POST 请求诊断”可查看最近记录。默认日志不保存简历和提示词正文；只有显式开启“记录完整 AI 请求与响应”后才保存有限长度正文，可随时清空。

提示词的业务内容可以完全自定义，支持以下变量：

- `{{resumeSummary}}`：个人简历摘要
- `{{jobTitle}}`、`{{companyName}}`、`{{jobArea}}`、`{{jobSalary}}`
- `{{jobEducation}}`、`{{jobExperience}}`、`{{companyIndustry}}`、`{{companyScale}}`
- `{{hrName}}`、`{{hrTitle}}`

不需要简历摘要时，可以从模板中删除 `{{resumeSummary}}`；模板使用了该变量但摘要为空时，扩展会明确提示。为了满足猎聘输入限制，纯文本、最多 150 字、最多 3 句话是不可关闭的发送安全边界。

兜底只覆盖 AI 请求失败或生成结果无效等“页面发送前”故障。若猎聘页面已经点击发送但回执未知，扩展仍会停止并要求人工核对，不会用兜底再次发送。诊断中的 Authorization 始终脱敏为 `[REDACTED]`；开启完整日志后可能包含简历摘要和岗位提示词，仅保存在当前 Chrome 扩展本地存储。

OpenAI 官方接口使用 `https://api.openai.com/v1`。智谱常规 OpenAI 兼容接口使用 `https://open.bigmodel.cn/api/paas/v4`；本机兼容代理可填写类似 `http://127.0.0.1:3001/v1` 的地址。不要把 GLM 模型与 OpenAI 官方 Base URL 混用。

> 猎聘在建立新沟通时可能先自动发送账号中配置的默认招呼语。当前页面模式无法阻止平台这一步，因此 AI 文本会作为后续个性化消息发送，而不是替换平台默认招呼。

## 当前页顺序投递

1. 先完成一次单岗位真实验收，确认当前页面的 AI 消息与简历回执均正常。
2. 在“当前页面 / 顺序投递全部新岗位”设置动作与岗位随机等待及账号安全护栏；默认动作间等待 1.5–3.5 秒、岗位间等待 5–15 秒、单批最多 10 个、每日最多 30 个，每明确成功 5 个后冷却 180 秒。
3. 点击“顺序投递当前页”，核对新岗位和已联系岗位数量，再点击“确认并开始”。
4. 批量模式会冻结确认时的当前页岗位顺序，并在滚动/沟通、聊天/招呼、文本/发送、招呼/简历、弹窗/确认和简历/关闭聊天之间分别等待一个随机动作间隔；不会逐岗弹出草稿预览。
5. 任一岗位出现验证码、登录失效、访问/操作频繁、账号异常、聊天绑定不明或发送回执不完整时，整个批次立即停止。运行中可点击“停止顺序投递”。

每日新投递数和长冷却截止时间保存在当前 Chrome 配置中，收起页内抽屉或重启浏览器不会清零；“继续聊”不计入新投递额度。收起抽屉只隐藏界面，不会停止正在运行的批次；如需停止必须先点击“停止顺序投递”。批量仅覆盖当前已加载页面，不自动翻页，也不会在刷新页面或重启浏览器后自动恢复。

这些等待用于页面稳定、降低连续误操作并给停止/验证信号留出响应时间，不能保证账号绝对不会受限。扩展不实现伪造鼠标轨迹、指纹伪装、验证码绕过、隐藏自动化特征或其他规避平台风控的行为。

## 本地构建

```powershell
npm install
npm run check
```

构建产物位于 `dist`。

## 加载插件

1. 打开 `chrome://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目的 `dist` 目录。
5. 已加载过旧版本时，必须在扩展卡片上点击一次“重新加载”。
6. 刷新已经打开的猎聘页面。
7. 页面会自动展开 `Get Jobs 助手` 固定抽屉；可用右下角悬浮按钮、抽屉关闭按钮或 Chrome 工具栏图标切换显示。

## 猎聘单岗位验收

1. 在真实 Chrome 中登录猎聘，并打开岗位搜索结果页。
2. 手动关闭已有聊天窗口或验证弹窗。
3. 在页内助手抽屉点击“重新识别”。
4. 完成 AI 配置并保存，选择一个用于验收的岗位，点击“生成草稿”。
5. 核对并按需编辑草稿，点击“确认并发送”。若已关闭预览，则点击“生成并投递”。
6. 确认猎聘依次出现当前岗位聊天窗口、AI 招呼消息和本人简历卡片。
   若出现“选择附件简历”，0.2.5 会使用页面已选中的附件点击唯一“立即投递”按钮，无需人工接管。
7. 回到页内助手抽屉确认“沟通、招呼、简历”三个阶段均为成功；若任一阶段显示“待核对”，必须先检查聊天记录，不要立即重试。
8. 若按钮原本是“继续聊”，应记录为“此前已联系”，并为避免重复而不发送新消息或简历。

## 安全边界

- 插件不会绕过验证码、安全验证或平台限流。
- 页面刷新或浏览器重启后不会自动重复点击，会将任务标为“已中止”并要求人工核对。
- AI 接口仅允许 HTTPS，或本机 `localhost/127.0.0.1` 的 HTTP 地址；配置地址不得包含用户名或密码。
- 用户关闭预览确认后，点击“生成并投递”即授权本次 AI 草稿生成完成后继续发送消息和简历。
- “确认并开始”会授权当前页批次中的每个新岗位直接发送 AI 草稿与按配置发送简历；请先完成单岗位验收。
- 当前不包含批量翻页、断点自动恢复、BOSS 或智联适配器。
